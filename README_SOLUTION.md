# Solution: Ghost Data Still Exists

The deletion-audit agent lives in `code/`. Full setup, run instructions,
architecture and design decisions are in **`code/README.md`**.

Quick start (repository root, Python 3.10+):

```bash
python3 code/main.py                        # writes output.csv (518 rows)
python3 code/validate_output.py             # contract check on output.csv
python3 code/evaluation/main.py --custom    # scores sample + custom cases
python3 code/main.py --explain case_11      # evidence trail, policy rule and exposed fields for one case
python3 code/main.py --exposures exposures.csv   # per finding: which identifier fields still expose the person
python3 code/evaluation/test_engine_rules.py     # 46 offline checks: policy file, retention, exposures, schedule
python3 code/evaluation/holdout_tests.py         # 2-fold hold-out of account and worker-row attribution
python3 code/evaluation/build_report.py          # evaluation_report.md, every number computed by code (--check verifies)
```

The deletion policy is read from `dataset/deletion_rules.csv` at run time, and
the deletion worker's timing is learned from the participant data at run time.

Optional model layer (keys from the environment or an uncommitted `.env` in
this folder; copy `.env.example`, never package or commit `.env`):

```bash
cp .env.example .env             # fill in GEMINI_API_KEY (recommended) or GROQ_API_KEY / ANTHROPIC_API_KEY
python code/main.py --doctor     # checks OCR, keys and which models your key can use
python code/main.py --use-llm --llm-classify all --require-llm
python code/evaluation/usage_report.py --write      # rewrite usage_report.md from that run
python code/evaluation/test_llm_adapters.py         # 51 offline model-layer checks, no keys needed
python code/evaluation/compare_models.py            # Gemini vs Groq comparison -> code/evaluation/model_comparison.md
python code/package_submission.py                   # code.zip with a secret check (.env never included)
```

Reports (the challenge requires the evaluation and usage reports):

* `code/evaluation/evaluation_report.md` (generated by `build_report.py`):
  accuracies on the 32 sample cases, five custom cases, cross-validated
  hold-out tests, offline test results, full-run statistics, exposed-field
  summary, the final model run, the model comparison, failures found and
  improvements made.
* `code/evaluation/model_comparison.md` (generated by `compare_models.py`):
  Gemini vs Groq on all requests and screenshots.
* `code/evaluation/usage_report.md` (generated by `usage_report.py` from the
  final run's `usage_run.json`): providers, models, calls, tokens and cost of
  the run that produced `output.csv`.
